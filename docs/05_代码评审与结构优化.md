# 05 代码评审与结构优化

> 评审时间：2026-08-22 · 范围：`New Tuanjie Project/Assets/Game` 全部 C# 代码 + `docs/` 文档
> 目标：在不改变玩法/行为的前提下，修复缺陷、消除冗余、统一结构。

## 一、审查结论（总览）

项目整体结构清晰、职责划分良好（xNode 决策 / Slate 时序 / ScriptableObject 配置），
命名与注释规范，玩家与敌人共用战斗/技能系统的一致性保持得不错。
主要问题集中在：**计时逻辑重复**、**配置字段未被消费**、**每帧分配**与**少量死代码/格式问题**。

## 二、修复的问题

### 1. 功能性缺陷

| 问题 | 位置 | 影响 | 修复 |
|---|---|---|---|
| `StateTime` 双重累加 | `EnemyStateMachineRunner.Update` 已统一推进，但 `IdleStateNode.Tick` 与 `InvestigateStateNode.Tick` 又各自 `+= deltaTime` | Idle→Patrol、Investigate→Return 的 `TimerElapsed` 条件以**双倍速度**触发（配置 2s 实际约 1s） | 删除节点内重复累加，`StateTime` 统一由 Runner 管理；节点只读 |
| 近战 `ActiveDuration == 0` 时永不命中 | `MeleeWeapon.AttackRoutine` 使用 `while (activeTime < ActiveDuration)` | 配置 0 秒活动期时一次伤害都不结算（"挥空"） | 改为 `do…while`，保证至少结算一次命中 |
| `CanHitMultipleTargets` 配置未消费 | `MeleeWeaponConfig` 有该字段但 `MeleeWeapon` 未读取 | 配置"单目标"无效 | 命中后按配置 `break`，单目标武器只结算第一个目标 |

### 2. 测试修复（PlayMode T8/T11 原有失败）

审查中发现 `EnemyAiPlayModeTests` 的 T8/T11 在改动前即失败（用原始代码复跑确认）。根因与修复：

| 测试 | 原失败根因 | 修复 |
|---|---|---|
| T11 双敌人共享图 | 敌人2放在 (0,0,-10)，距玩家 (0,1,5) 为 15m > 视野 10m，永远看不到；改近后又撞上墙体 `Wall_1`（x=2）遮挡视线 | 敌人2移到 (0,0,3)：距玩家约 2m、视线沿 x=0 无遮挡、在 NavMesh 上 |
| T8 丢失目标后回巡逻 | ① PlayMode 会话带 Main 场景，Main 玩家 (5.52,1,3.5) 距测试敌人 6.6m 被误锁，移动测试玩家后仍"可见"；② 测试场景无烘焙 NavMesh，运行时 NavMeshAgent 无法绑定（"no valid NavMesh"），Motor 失效 → 状态机卡在 Return | ① 新增 `MoveScenePlayerAway()` 隔离 Main 玩家；② 测试类增加 `[UnitySetUp]` 显式加载 Main 场景以提供 NavMesh（与 `PlayerSkillCombatPlayModeTests` 一致） |

> 说明：PlayMode 测试此前在 `docs/04` 中一直标记为"待本地验证"，本次一并修复并通过（8/8）。

## 三、本次未改动（记录备查）

- **`CharacterSkillController` 与 `PlayerController` 的耦合**：技能控制器直接引用玩家控制器做移动锁定。
  敌人复用同一控制器时该引用为空（不影响敌人，施法中状态守卫已停住移动）。
  后续可抽象 `IMovementLockable` 接口解耦，本次为避免改动序列化接线暂不实施。
- **测试用反射访问私有字段**（`EquipTestWeapon`、`SetField` 等）：工作正常但较脆弱，
  后续可用 `InternalsVisibleTo` 或测试专用内部 API 替换。
- **`HealthBarHUD` 每帧 `GetComponentInParent`**：数据量小，暂可接受。
- **`Projectile` 对象池**：场景弹丸量小，暂不需要。
